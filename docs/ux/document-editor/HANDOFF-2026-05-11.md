# 문서 편집 페이지 작업 인수인계 - 2026-05-11

오늘 작업은 `/documents/{documentId}` 문서 편집 페이지의 우측 인스펙터 탭 구조를 기준으로 UX 가이드 문서를 정리하는 데 집중했다.

---

# 1. 오늘 확인한 현재 구현 상태

현재 구현 파일:

* `src/pages/DocumentEditor.jsx`
* `src/pages/DocumentEditor.css`

현재 `/documents/1` 페이지는 다음 구조로 구현되어 있다.

* 좌측 문서 편집 영역
  * breadcrumb
  * 문서 제목
  * 문서 메타 칩
  * 편집 툴바
  * 본문 캔버스
  * 문서 상태바
* 우측 인스펙터
  * `속성`
  * `AI 어시스턴트`
  * `활동`

우측 탭 전환은 `useState`로 동작한다.

현재 화면은 아직 정적 목업 성격이 강하다. 실제 API 연결, 저장, AI 요청, 문서 선택 영역 연동, 활동 로그 조회는 아직 구현되지 않았다.

## 3.1 `README.md`

다음 작업자가 어떤 문서를 먼저 봐야 하는지 확인할 수 있다.

`/documents/{documentId}` 페이지 전체 구조를 설명한다.

포함 내용:

* 속성/AI 어시스턴트/활동 탭 역할
* 주요 사용자 흐름
* API 연결 방향
* 권한/보안 원칙

## 3.3 `notive-document-editor-canvas-guide-v1.0.md`

좌측 문서 편집 영역 가이드다.

포함 내용:

* meta chips
* editor toolbar

* 권한 기준

* 데이터/API 연결 기준

## 3.5 `notive-document-editor-ai-assistant-guide-v1.0.md`

* 컨텍스트 요약 카드

* 문서별 활동 API 필요 사항

# 4. 다음에 이어서 할 작업 후보

## 4.1 문서 편집 페이지 기능 연결

우선순위가 높다.

* 실제 문서 상세 데이터 연결
* 제목/본문 편집 상태 관리
* 저장 상태 연결
* 태그/문서 유형 상태 연결
* 버전 목록 데이터 연결

## 4.2 AI 어시스턴트 기능화

현재 UI는 구성되어 있으나 동작은 목업이다.

다음 작업이 필요하다.

* 빠른 작업 버튼별 `actionType` 정의
* 프롬프트 입력 상태 관리
* 참고 자료 선택 상태 관리
* 현재 문서 본문 또는 선택 영역을 AI 요청에 포함
* 생성 진행/실패/결과 상태 표시
* 삽입/선택 영역 교체 실제 반영

현재 API 명세에는 문서 편집기용 AI 보조 모드가 별도로 없다.

`POST /organizations/{organizationId}/ai/generate-document`를 확장하거나 별도 API를 설계해야 한다.

## 4.3 활동 탭 기능화

현재 활동 탭은 정적 타임라인이다.

다음 작업이 필요하다.

* 활동 필터 상태 관리
* 실제 문서별 활동 로그 API 설계 또는 기존 관리자 로그 API 필터 확장
* 이벤트 카테고리 표준화
* 버전 보기/복원 내역 보기 액션 연결
* 본문 원문과 AI 요청 원문을 로그에 노출하지 않는 정책 유지

## 4.4 반응형 처리

현재 1024px 이하에서 우측 인스펙터가 숨겨진다.

후속으로 다음을 검토해야 한다.

* 모바일/태블릿에서 인스펙터를 하단 패널이나 drawer로 제공할지
* AI 어시스턴트와 활동 탭을 모바일에서 어떻게 진입시킬지

---

# 5. 주의할 점

* AI 결과는 항상 초안이다.
* 사용자의 명시 액션 없이 문서를 덮어쓰면 안 된다.
* 권한 없는 문서, 다른 조직 문서, 삭제된 문서는 AI 참고 자료로 쓰면 안 된다.
* 출처 없는 답변을 근거 기반 답변처럼 보여주면 안 된다.
* 활동 로그에는 문서 본문 원문, AI 요청 원문, 검색어 원문을 저장하거나 표시하지 않는다.
* Admin도 MVP에서는 조직 전체 문서 본문을 묵시적으로 열람하지 않는 정책이다.
